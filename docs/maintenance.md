# 验证与 GitHub 维护流程

更新：2026-10-11。

## 每次修改

1. 检查两个仓库分支和工作区，fetch 远端确认基线。明确改动范围，保留其他人的未提交内容。
2. 改代码时同步更新功能文档和 API；改权限/字段/流程必须写清规则、源码位置、错误响应、兼容性及未实现部分。新迁移一起提交。
3. 做适当验证，记录实际命令、结果和环境，不虚构覆盖。前后端共同改动需在两端文档说明关联接口。
4. 检查暂存文件及 diff，不提交环境、凭据、个人资料、备份、上传文件或 dist/node_modules。
5. 按完整功能或修复提交，消息说明具体行为。提交并 push 当前协作分支；不得 force push。前后端各自推送，在交付中给出两端提交。
6. 部署时记录两端提交 SHA；备份后同步/构建，迁移后检查公开入口。发布后的附加修复也要再更新文档并提交，不留下仅服务器存在的修改。

GitHub 当前后端维护分支 master，前端维护/发布分支 main。2026-10-11 经用户授权，已将前端 yzh24 快进合入 main 并推送；yzh24 保留协作历史。后续其他分支的推送不会自动合入 main，需明确合并并验证。

## 后端验证

```sh
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test apps.user apps.event apps.file apps.notification apps.management --verbosity=2
```

测试应在独立数据库和测试邮件后端运行。行锁/并发必须在 PostgreSQL 上验证，测试账号需有创建测试库权限或预建测试库；不要向正式数据库手工跑测试迁移。apps/management/tests.py 和 user 回归模块使用隔离缓存/快速哈希，生产配置不应因此改变。

| 测试位置 | 覆盖 |
|---|---|
| apps/user/tests.py | 注册、验证码、登录、资料、邮箱/密码、头像基础规则 |
| apps/user/test_role_login.py | 选定身份、多身份授权、普通账号越权、资源所有权 |
| apps/user/test_account_regressions.py | 更换学号后登录、短密码、验证码并发消费 |
| apps/event/tests.py | 状态、教师所有权、报名、改判、中途审批、容量 |
| apps/file/tests.py | 上传分类/大小、文件绑定和下载权限、引用保护、模板 |
| apps/notification/tests.py | 通知生成、本人已读和他人访问限制 |
| apps/management/tests.py | 管理集成、分页、并发最后名额、重复申请、账号删除释放名额及并发删除/审批 |

2026-10-11 完整生产同环境 PostgreSQL 回归 90 项通过。公网 174 条历史检查记录及复测解释见 qa/；文档修改不能被当成重新跑过这些业务测试。前端 build/lint 另在前端仓库执行。

## 最小跨角色人工联调

学生/教师公开注册 → 各自登录 → 资料和头像 → 教师草稿/附件/发布 → 学生详情/简历/报名 → 教师审核 → 学生看到结果 → 管理员查看统计/用户/项目/申请/文件/资料库。另检查普通账号直达管理员接口被拒绝，以及进行中待审申请可审核而已完成结果不可改。

邮件送达需要真实收件确认；预置验证码只验证注册，不代表 SMTP 送达。测试项目用明确测试前缀，按既有业务规则关闭或停用，测试凭据私下保存。

## 已知未实现与范围限制

- 通知后端已有，前端通知页面未实现。
- 忘记密码流程未实现；已有登录后改密码和管理员重置。
- 撤回申请未实现；模型 cancelled 不表示已有功能。
- 知识库没有文章编辑/全文检索。
- 教师注册无人工审核；can_recruit 筛选不包含 ongoing，见 features.md。
- 扩展名/大小校验不等于病毒扫描；上传孤儿文件、旧验证码、备份没有自动保留期清理。
- 默认进程内限流缓存不提供跨 worker 统一额度；未做长期压力、全部设备/浏览器覆盖。
- ICP 备案/接入审核未独立核验，域名放行、HTTPS 成功不能代替审核证明。

## 文档更新范围

新增页面或接口要更新 README 导航、features、API、CHANGELOG；部署或配置变化更新 deployment；测试策略或已知缺口变化更新本文件。历史 qa 记录保留原始失败与复测说明，不能把旧失败直接改写为成功。
